## 1. 화면 구성

흐름은 둘이다 — **찾아서 연다**(①→②), **만들어서 등록한다**(③→④).

| # | 화면 | 파일 | 담는 것 |
|---|---|---|---|
| ① | 앱 찾기 | `Main.dc.html` | 검색, 업무 분야 탭, 앱 카드(열기 / 권한 신청) |
| ② | 앱 상세 · 열기 | `AppDetail.dc.html` | 앱 열기, 소개, 앱 정보(제작 · 대상 사용자 · 내 권한 · 보이는 데이터 · 보안 검증 · 버전) |
| ③ | 앱 등록 | `Register.dc.html` | 등록 양식 + 등록 후 진행 4단계 안내 |
| ④ | 등록 현황 | `MyApps.dc.html` | 등록한 앱별 진행 단계(신청 → 플랫폼팀 검토 → 보안 검증 → 배포 승인 → 공개) |

`.dc.html`은 Claude Design 캔버스의 원본이며 단독 브라우저 실행용이 아니다. `canvas.json`은 캔버스 배치 정보다. 수정은 캔버스에서 하고 여기는 이력 보관용이다.

### 1-1. 앱은 함께 쓴다 — 화면 문구 원칙

앱은 런타임에 하나 떠 있고 여러 사람이 동시에 접속한다. 사용자가 앱을 띄우는 것이 아니다. 그래서 사용자에게 보이는 문구는 **"실행" 대신 "열기"** 를 쓴다(내부 용어 `launch` · `/launch`는 유지, `AXM-0009`).

- **보이는 데이터는 사람마다 다르다** — OBO로 각자 권한 범위만 조회한다. 상세 화면에 "보이는 데이터: 내 권한 범위만"으로 표시. SP 모드 예외 앱은 "모든 사용자에게 같은 데이터"로 달리 표시해야 한다(목업 미반영)
- **유휴 정지된 앱은 그날 처음 연 사람만 기다린다** — 상세 화면에 한 줄 안내 (`06` §6-3)
- **비용 · 용량은 사용자 수가 아니라 앱 단위다** — 등록 양식에서 이용 규모를 받는다(§2-1)
- 메뉴 "내 앱"은 임직원에게 "내가 쓰는 앱"으로 읽히므로, 등록한 앱의 진행 화면은 **"등록 현황"** 으로 이름을 바꿨다

**스타일**: 흰 바탕 · 검정 단일 주조 · 회색 구분선. 색은 보안 검증 통과 표시(초록)만 쓴다. 서체는 IBM Plex Sans KR. 데이터는 전부 예시값이다.

## 2. 앱 등록 프로세스

**등록은 앱마켓에서 한 번에 끝나지 않는다.** 앱마켓은 처음(신청)과 끝(공개)만 맡고, 중간은 GitLab과 Playground에서 일어난다.

| 단계 | 어디서 | 누가 | 무엇을 | 목업 |
|---|---|---|---|---|
| 신청 | 앱마켓 | 개발자 | 등록 양식 제출 | ③ |
| 플랫폼팀 검토 | 앱마켓 | 플랫폼팀 | 실행 환경(런타임) 결정, 신청 내용 확인 | ④ |
| 보안 검증 | GitLab 파이프라인 | 자동 | SAST · SCA · SBOM · Secret · 서명 (`02` §4) | ④ |
| 배포 승인 | GitLab 보호된 환경 | 승인자 | 운영 배포 승인 (`02` §3) | ④ |
| 공개 | 앱마켓 | 자동 | 조정 루프가 운영 상태를 확인하면 대상 사용자에게 노출 (`06` §6-4) | ④ → ① |

### 2-1. 등록 양식 항목

| 구분 | 항목 | 비고 |
|---|---|---|
| 기본 정보 | 앱 이름 · 한 줄 설명(목록 표시, 50자) · 상세 설명 | |
| 제작자 | 담당자(로그인 정보 자동) · 부담당자 | 부담당자 = `03` §6-2 `owner.backup`. 퇴사 · 이동 시 방치 방지 |
| 대상 사용자 | 유형: 전 임직원 / 특정 조직 / 특정 직무 / 지정 사용자 + 범위 지정 | `03` §6-2 `authz.visibility` · `ad_groups`로 투영 |
| 이용 규모 | 최대 동시 사용자(10 / 50 / 200 / 200 초과) · 이용 시간대(업무시간 / 24시간 상시) | `03` §3 **Q8′ · Q8**을 신청자 언어로 바꾼 것. 상시 운영은 플랫폼팀 비용 협의 |
| 소스 코드 | Git 저장소 주소 | Playground 저장소 여부와 표준 파이프라인 연결을 확인해 표시 |

## 3. 목업에서 정한 것 — 확인 필요

| # | 결정 | 영향 |
|---|---|---|
| 1 | **런타임 판정 질문을 나눴다.** Q8 · Q8′(이용 시간 · 규모)은 쉬운 질문으로 바꿔 양식에 두고, Q1~Q7(기술 판단)은 플랫폼팀 검토 단계로 보낸다 | `03` §3 "등록 신청서 양식용 체크리스트"와 다르다. 확정 시 `03` 개정 또는 ADR 필요 |
| 2 | **업무 분야를 양식에 넣지 않았다** | ① 화면이 분야 탭으로 분류하므로, 양식에 넣을지 플랫폼팀이 지정할지 정해야 한다 |
| 3 | **스토어 노출 정보(설명 · 화면 캡처)를 신청 시점에 받는다** | 설계 문서에 "임직원이 보는 정보를 언제 누가 채우는가"가 정의되어 있지 않았다. 공개 전 수정 가능 여부는 미정 |
| 4 | 데이터 등급(C1~C3)은 양식에 없다 | A5(데이터 등급 체계) 확정 후 추가 |
