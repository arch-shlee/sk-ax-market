# AXM-0013: 앱마켓 인프라 아키텍처 특성 — 보안성 · 감사 가능성 · 상호운용성 · 가용성 · 운영 용이성

- **상태**: Accepted
- **일자**: 2026-09-27
- **결정자**: 아키텍처
- **관련 문서**: `05` §2~§5, `06` §4·§5, `07`, `AXM-0003`, `AXM-0007`, `AXM-0009`, `AXM-0011`, `AXM-0012`

## 맥락

앱마켓 인프라(컴퓨트, NLB 배치, DB, 증적 저장소)를 본격적으로 구성하기 전에 **무엇을 우선해 최적화하는지**를 정해 둔다. 이후 인프라 결정이 서로 부딪칠 때 이 순위를 판단 근거로 쓴다.

작용하는 사실:

- 사용자 진입은 DX 경유, 인터넷 노출 없음 (F5, `AXM-0003`)
- 앱 실행은 리다이렉트 — 앱 트래픽이 마켓을 통과하지 않는다 (`AXM-0009`)
- 마켓은 GitLab · Databricks · VKS · 온프렘 DNS를 사설 경로로 봐야 하고, SSO 중계인 Cognito(`AXM-0014`)는 퍼블릭 도메인 엔드포인트로만 도달한다 — 사내 리버스 프록시로 이그레스를 한 곳에 모은다(`AXM-0015`)
- 증적은 어떤 상태에서도 삭제하지 않는다 (`06` §4-4)
- 운영 주체·당직 체계 미정, PoC는 1인 운영 (`05` §7)

## 결정

> 앱마켓 인프라는 **① 보안성 ② 감사 가능성 ③ 상호운용성 ④ 가용성 ⑤ 운영 용이성** 순으로 최적화한다. 성능·확장성·탄력성·비용은 구동 특성으로 두지 않는다.

| # | 특성 | 의미 | 측정 기준(안) |
|---|---|---|---|
| 1 | **보안성** (사설 경계 · 최소 노출) | 신뢰 경계와 노출 지점을 최소화한다 | **인바운드 퍼블릭 경로 0**(이그레스 전용 NAT는 로그인 프록시에만, `AXM-0015`), 진입/애플리케이션 서브넷 분리, 계정 간 허용 주체 명시 |
| 2 | **감사 가능성** (증적 불변성) | 누가 무엇을 승인·배포·실행했는지 사후 재구성 가능 | 증적 저장소 Object Lock + 버전 관리, 플로우·ALB·NLB 로그 수집률 100%, 보존 기간 |
| 3 | **상호운용성 · 연결성** | 외부 권위 소스와 사설 경로로 안정적으로 연동 | 연동 대상별 경로·DNS 해석 검증표, 조정 루프 성공률 |
| 4 | **가용성** (진입점 등급) | 검색·실행 클릭이 끊기지 않는다 | Multi-AZ, RDS PITR, RTO/RPO (수치는 SLA 등급 정의 후) |
| 5 | **운영 용이성** | 소수 인력으로 운영 가능 | 관리형 서비스 비율, IaC 적용 범위, 롤백 시간 |

## 근거

**구동 특성에서 뺀 것**

- **성능 · 확장성 · 탄력성** — 리다이렉트 구조라 마켓은 저트래픽 서비스다. 임직원 1만 명 기준 피크 초당 수십 건 (`05` §5-1). 앱 용량은 런타임이 푼다(Q8′)
- **비용** — 마켓 자체 비용은 작다. 비용 통제는 런타임 정책(`AXM-0005`)이 맡는다

**감사 가능성을 보안성에서 분리한 이유** — 증적 저장소(Object Lock, 보존 정책, 삭제 방지)라는 **독자적인 인프라 요소**를 만들어 내므로 별도 특성으로 둔다.

## 결과

**얻는 것**
- 컴퓨트·NLB 배치·DB·증적 저장소 결정이 같은 기준으로 비교된다
- 성능 최적화에 드는 설계 비용을 의도적으로 쓰지 않는다

**감수하는 것**
- **보안성 ↔ 상호운용성 긴장.** 연동이 늘 때마다 노출 지점이 생긴다. 내부 NLB 배치(`05` §1-2)가 이 충돌의 실제 지점이다
- **가용성의 상한은 마켓 밖에 있다.** 로그인이 Cognito(`AXM-0014`), 원천 IdP, 로그인 프록시·NAT(`AXM-0015`)에 의존하므로, 마켓을 Multi-AZ로 올려도 이들의 가용성을 넘지 못한다

## 검토한 대안

| 대안 | 평가 | 기각 사유 |
|---|---|---|
| 확장성·성능을 상위에 두기 | 일반적인 웹 서비스 기본값 | 리다이렉트 결정(`AXM-0009`)으로 부하 근거가 사라졌다 |
| 감사 가능성을 보안성에 통합 | 특성 수가 줄어 단순 | 증적 저장소가 독자 인프라 요구를 만든다 |
| 운영 용이성을 3위로 | 인력이 매우 적다면 합리적 | 운영 인력 규모 미정. 확정되면 재검토 |

## 미결 / 후속

- **A5(망분리·데이터 등급)** 확정 시 보안성의 강도 재조정. 그 전까지 C2(내부) 가정
- **SLA 등급 정의**(`03` §8 #12) 후 가용성 측정 기준에 RTO/RPO 수치 기입
- 운영 인력 규모 확정 시 ④·⑤ 순위 재검토
