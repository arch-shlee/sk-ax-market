# AXM-0002: 클라우드·계정 토폴로지

- **상태**: Accepted
- **일자**: 2026-09-12
- **결정자**: 인프라 / 플랫폼
- **관련 문서**: `05-physical-architecture.md` §1, `03` 확정된 전제 F1·F2·F6

## 맥락

앱마켓과 두 런타임을 어느 클라우드의 어느 계정에 둘 것인가. 이것이 정해지지 않으면 인증 설계(Keycloak 연동 가능 여부), 네트워크 경로, 비용 귀속 단위가 모두 미정으로 남는다. 종전 설계는 "어느 클라우드인가"를 최우선 미결 항목으로 두고 있었다.

## 결정

> **AWS · ap-northeast-2(서울)** 를 사용하고, **Databricks 전용 계정 / 앱마켓 운영 전용 계정 / Playground 계정**을 분리한다.

| 계정 | 역할 | 상태 |
|---|---|---|
| Databricks 전용 | 워크스페이스, UC 메타스토어, SQL Warehouse | 기존 |
| **앱마켓 운영** | AX App Market 서비스 | **신규** |
| Playground (259537089696) | Coder 개발환경 | PoC 가동 중 |
| 공유 네트워크 | TGW · DX · DNS | **존재 여부 확인 필요** |

Databricks 계약은 **Enterprise tier**다.

## 근거

- Playground PoC가 이미 AWS ap-northeast-2에 있고, 앱마켓도 AWS에 별도 구현하기로 했다
- 계정 분리는 Playground PoC의 `ADR-0002`(dual-account) 원칙과 정합한다
- PoC 도면 자신이 경고하고 있다 — "VPC 작음(/22)에 타인 자원 공존 → 운영 계정은 전용 신규 VPC"

## 결과

**얻는 것**
- **AWS이므로 Entra ID 고정 제약이 없다.** Keycloak을 OIDC IdP로 하는 직접 연동 경로가 열린다 (종전 가정 A2 해소)
- **서울 리전이므로 개인정보 국외이전 쟁점이 해소**된다
- **Enterprise tier이므로 NCC 사설 엔드포인트와 네트워크 정책을 쓸 수 있다** → `AXM-0004`가 여기 걸려 있다
- 계정 경계가 곧 비용 귀속 경계가 된다

**감수하는 것**
- **cross-account 구성의 복잡도.** 앱마켓 → Databricks REST API, NCC 사설 엔드포인트가 모두 계정을 넘는다
- 계정마다 TGW attachment·DNS·로깅을 각각 구성해야 한다
- 신규 계정의 **VPC CIDR 확보 리드타임** — 사내 IP 대역 관리 부서 협의

## 검토한 대안

| 대안 | 평가 | 기각 사유 |
|---|---|---|
| 앱마켓을 기존 Playground 계정에 동거 | 계정 신설 불필요 | /22 VPC에 타인 자원이 이미 공존. 운영 서비스를 개발 계정에 두는 것은 격리 실패 |
| 앱마켓을 VKS(온프렘)에 배치 | 기구축 자원 활용, 비용 0에 가까움 | Databricks API·시스템 테이블 질의가 주 업무인데 경로가 멀어진다. 앱마켓은 AWS 배치로 결정됨 |
| 앱마켓을 Databricks Apps에 배치 | 인프라 불필요 | 앱마켓이 자신이 관리하는 런타임에 종속된다. 워크스페이스 장애 시 진입점까지 동반 정지 |

## 미결 / 후속

- **공유 네트워크 계정의 존재 여부**와 TGW 소유·RAM 공유 방식
- **내부 NLB를 어느 계정에 둘 것인가** (`05` §1-2) — `AXM-0004` 경로의 운영·감사 주체가 여기서 정해진다
- 앱마켓 운영 계정 CIDR 확보 (리드타임 최장)
