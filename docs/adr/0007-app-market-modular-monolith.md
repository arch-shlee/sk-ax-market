# AXM-0007: 앱마켓 아키텍처 스타일 — 모듈러 모놀리스 + 레지스트리/프로젝션

- **상태**: Proposed
- **일자**: 2026-09-12
- **결정자**: (승인 대기)
- **관련 문서**: `cicd-devsecops-research.md` §4, `03` §6, `05` §5

## 맥락

앱마켓은 다섯 문서 내내 구성도의 박스 하나였다. 실제로 만들려면 스타일을 정해야 한다.

**중요한 관찰**: 선행 조사는 앱마켓을 IDP(Internal Developer Portal)로 규정했고 그 프레이밍은 유용했으나 **절반만 맞다.** 앱마켓은 얼굴이 둘이다.

| | 개발자 포털 | 사내 앱스토어 |
|---|---|---|
| 사용자 | 개발자·플랫폼팀·승인자 (수십~수백) | **전 임직원 (수천~수만)** |
| 하는 일 | 등록·스캐폴딩·증적·승인·소유권 | 검색·권한 신청·**실행** |
| 사례 | Backstage, Port, Cortex | Google Gemini Enterprise Agent Gallery |

Backstage 계열은 왼쪽만 다루고 UI도 개발자용이다.

## 결정

> **모듈러 모놀리스** 위에 **레지스트리 + 프로젝션** 구조를 둔다. 임직원용 스토어와 개발자·운영 콘솔은 **두 개의 시스템이 아니라 같은 레지스트리 위의 두 프로젝션**으로 만든다.

**모듈 경계** (같은 프로세스, 분리된 스키마)

```
catalog      검색 · 분류 · 상세 (프로젝션)
registry     엔티티 · 프로바이더 · 조정 루프 (진실의 원천)
authz        공개범위 · AD 그룹 · CAN_USE 오케스트레이션
evidence     SBOM · 서명 · 승인 이력 (불변, 감사 대상)
ingest       지표 · 비용 정규화 계층        ← 분리 1순위 후보
```

## 근거

**레지스트리 + 프로젝션** — 사내 에이전트 마켓플레이스 설계 관례가 명확하다. "마켓플레이스는 거버넌스된 레지스트리 위의 임직원용 뷰로 동작하며, **레지스트리가 진실의 원천**이고 검색·추천·컬렉션은 그 기록의 **프로젝션**이다." Backstage의 stitching(처리된 엔티티 + 관계를 하나의 가시 객체로 병합)도 같은 형태다. → **`03` §6 스키마를 화면에 맞추지 말고 레지스트리에 맞춘다.**

**모듈러 모놀리스** — 2026년 기본값이다. Amazon Prime Video의 Video Quality Analysis 팀은 분산 구성에서 단일 프로세스로 되돌리며 인프라 비용 90% 절감을 보고했고, 마이크로서비스에서 디버깅에 약 35% 더 많은 시간이 든다는 조사도 있다. 앱 100~300개 · 팀 하나 규모에서 마이크로서비스를 택할 근거가 없다.

**`ingest`를 별도 모듈로 두는 이유** — 부하 특성이 다르다. 배치성이고, Databricks 시스템 테이블 질의라 지연이 크며, **실패해도 카탈로그 조회는 살아 있어야 한다.**

## 결과

**얻는 것**
- 단일 배포 단위. 운영 부담 최소
- 두 얼굴을 한 시스템으로 처리하면서도, 임직원 트래픽이 커지면 해당 UI만 떼어낼 수 있다
- 화면이 늘어도 레지스트리 스키마가 흔들리지 않는다

**감수하는 것**
- 모듈 경계는 **규율로만 유지된다.** 컴파일러가 강제하지 않으므로 리뷰에서 지켜야 한다
- 프로젝션 구조는 초기 구현이 단순 CRUD보다 무겁다
- `ingest`가 같은 프로세스에 있는 동안에는 무거운 배치가 요청 지연에 영향을 줄 수 있다 → 스레드/워커 격리 필요

## 검토한 대안

| 대안 | 평가 | 기각 사유 |
|---|---|---|
| 마이크로서비스 | 확장성 | 우리 규모에 근거 없음. 디버깅·운영 비용만 증가 |
| 두 시스템으로 분리 (개발자 포털 / 임직원 스토어) | 각 UX에 최적 | 레지스트리가 둘로 갈라지거나 동기화 문제가 생긴다. 같은 앱의 진실이 두 곳에 있으면 반드시 어긋난다 |
| 단순 CRUD 모놀리스 (프로젝션 없이) | 가장 빠름 | 카탈로그·대시보드·비용 뷰가 각자 스키마를 참조하게 되어, 화면이 늘 때마다 스키마가 흔들린다 |
