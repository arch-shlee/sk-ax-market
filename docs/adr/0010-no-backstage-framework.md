# AXM-0010: Backstage를 프레임워크로 채택하지 않는다

- **상태**: Proposed
- **일자**: 2026-09-12
- **결정자**: (승인 대기)
- **관련 문서**: `AXM-0007`, `AXM-0008`, `cicd-devsecops-research.md` §4

## 맥락

앱마켓을 자체 구축할 것인가, 기성 IDP를 채택할 것인가. 세 갈래가 있다.

| 제품 | 성격 |
|---|---|
| **Backstage** (Spotify) | **프레임워크.** 설치해서 쓰는 게 아니라 그 위에 포털을 만든다 |
| **Port** | **제품.** 메타데이터 주도 SaaS |
| **Cortex / OpsLevel** | **의견.** 스코어카드 중심 |

업계 기준선은 개발자 규모로 갈린다 — 50명 미만이면 상용이 싸고, 50~200명이면 2인 팀으로 Backstage, 200명 이상이면 전담 3~4인.

## 결정

> **Backstage를 프레임워크로 채택하지 않는다.** 대신 **Backstage의 데이터 모델과 조정 루프 설계를 차용해 자체 구축**한다. 상용 SaaS도 후보에서 제외한다.

차용 대상은 `AXM-0007`(레지스트리/프로젝션)과 `AXM-0008`(엔티티 프로바이더·조정 루프·고아 처리)에 명시되어 있다.

## 근거

**상용 SaaS 제외**
- **A5(망분리·데이터 등급)가 미정인 상태에서 SaaS는 후보로 올릴 수 없다.** Port/Cortex는 SaaS가 기본이다

**Backstage 프레임워크 제외**
- **UI가 개발자용이다.** 전 임직원 대상 스토어로 쓰기 어렵다(`AXM-0007`의 "얼굴 둘" 문제). 어차피 임직원 UI를 따로 만들어야 하면 Backstage를 얹는 이득이 절반으로 줄어든다
- **유지보수 부담이 크다.** self-host 인스턴스는 통상 3~15 FTE가 필요하고, 쓸 만한 인스턴스까지 6~12개월이 걸리며, 플랫폼 엔지니어링 시간의 30~40%가 플러그인 유지보수로 간다. "Backstage를 만들던 팀이 플랫폼 엔지니어링 팀이 아니라 Backstage 유지보수 팀이 되었다"는 표현이 반복된다
- 평균 채택률이 엔지니어의 약 10%라는 조사도 있다
- **우리 고유 요구가 기성 커넥터 범위 밖이다** — 온프렘 GitLab, Databricks Apps 특유의 게이트(OBO·`CAN_USE`·워크스페이스 100개 한도), AI-BOM, 한국어 UI, AD 연동

**그래도 차용하는 이유**
- 카탈로그 데이터 모델과 조정 루프는 **이미 검증된 설계**다. 재발명할 이유가 없다

## 결과

**얻는 것**
- 두 얼굴(임직원 스토어 / 개발자 콘솔)을 우리 요구에 맞게 설계할 수 있다
- 업그레이드·플러그인 유지보수 부담이 없다
- 망분리 결과가 어떻게 나오든 배치를 바꿀 수 있다

**감수하는 것**
- **카탈로그·검색·권한·증적을 전부 직접 만들어야 한다.** Backstage가 공짜로 주는 것을 포기한다
- 스캐폴딩·TechDocs 같은 개발자 포털 기능은 별도 판단 대상이 된다. 당장 필요하지 않다면 범위에서 빼는 편이 낫다
- "직접 만든 IDP"는 그 자체로 유지보수 대상이 된다. Backstage를 피한다고 유지보수가 사라지지 않는다 — **다만 우리가 쓰지 않는 기능의 유지보수는 하지 않게 된다**

## 검토한 대안

| 대안 | 평가 | 기각 사유 |
|---|---|---|
| Backstage 프레임워크 채택 | 카탈로그·플러그인 생태계 | 위 근거 |
| Port / Cortex (상용 SaaS) | 도입 속도 | A5 미정 상태에서 SaaS 불가. 우리 고유 게이트를 표현하기 어려움 |
| Backstage를 개발자 콘솔로만 쓰고 임직원 UI는 자체 구축 | 절충 | 레지스트리가 둘로 갈라진다(`AXM-0007` 기각 사유와 동일). 유지보수 부담은 그대로 |

## 미결 / 후속

- **A5가 확정되고 망분리 대상이 아니라면 이 결정을 재검토할 가치가 있다.** 그 경우 Port/Cortex의 도입 속도가 유효한 선택지가 된다
- 개발자 포털 기능(스캐폴딩·TechDocs·소유권 관리)을 범위에 넣을지 결정. 넣지 않으면 자체 구축 범위가 크게 줄어든다
- 범위 축소 지침: 실무 IDP 스택은 포털 + 오케스트레이션 + 스코어카드 조합인데, **오케스트레이션 자리는 GitLab CI + Databricks Bundles가 이미 차지하고 있다.** 앱마켓은 포털 + 스코어카드 역할만 맡는다
