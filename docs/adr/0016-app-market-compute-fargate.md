# AXM-0016: 앱마켓 컴퓨트는 ECS Fargate — 클러스터 2개(market · auth-proxy)

- **상태**: Accepted
- **일자**: 2026-09-27
- **결정자**: 아키텍처
- **관련 문서**: `05` §5-1·§5-2, `06` §5, `AXM-0007`, `AXM-0008`, `AXM-0013`, `AXM-0015`

## 맥락

`05` §5-2가 앱마켓 컴퓨트를 "결정 필요"(ECS Fargate 권고 / EKS / EC2)로 남겼다. 이후 두 가지가 정해졌다.

- 우선 최적화 특성: 보안성 · 감사 가능성 · 상호운용성 · 가용성 · 운영 용이성 (`AXM-0013`)
- 전사 로그인 경로에 **L4 리버스 프록시**가 필요하다 (`AXM-0015`)

앱마켓은 저트래픽 서비스다(`AXM-0009` 리다이렉트, `05` §5-1). 조정 루프(`AXM-0008`)는 **동시에 하나만** 돌아야 한다. 두 개가 돌면 upsert가 경합하고 고아 판정이 흔들린다.

## 결정

> 앱마켓과 로그인 프록시를 모두 **ECS Fargate**로 운영하되, **클러스터를 둘로 분리**한다. 앱마켓은 같은 이미지를 `web`과 `worker` 두 서비스로 띄운다.

| 클러스터 | 서비스 | 사양(안) | 진입 | 비고 |
|---|---|---|---|---|
| `market` | `web` | 0.5 vCPU / 1 GB × 2 (AZ 분산) | 내부 ALB | catalog · evidence · launch · authz |
| `market` | `worker` | 0.5 vCPU / 1 GB × 1 | 없음 | 조정 루프 · ingest · 그룹 동기화. **DB advisory lock으로 단일 리더 보장** |
| `auth-proxy` | `proxy` | 0.25 vCPU / 0.5 GB × 2 (AZ 분산) | 내부 NLB :443 | nginx stream, TLS 패스스루 (`AXM-0015`) |

**네트워크 배치** (앱마켓 운영 계정, 신규 VPC, 2 AZ)

| 서브넷 계층 | 자원 |
|---|---|
| 진입 | 내부 ALB(market), 내부 NLB(auth-proxy) |
| 애플리케이션 | Fargate 태스크 (퍼블릭 IP 없음) |
| 데이터 | Aurora PostgreSQL Multi-AZ. 증적은 S3 Object Lock (Gateway EP) |
| 이그레스 | NAT GW × 2 — **auth-proxy 전용.** market 서브넷 라우팅에는 NAT를 주지 않는다 |
| VPC 엔드포인트 | ECR(api·dkr) · S3 · CloudWatch Logs · Secrets Manager · KMS · STS · Databricks front-end PrivateLink |
| TGW 경로 | GitLab · VKS · 사내 DNS (온프렘) |

## 근거

- **운영 용이성(⑤)**: 노드 관리가 없다. 저트래픽 서비스 몇 개에 EKS 클러스터를 운영할 이유가 없다
- **가용성(④)**: `web`과 `proxy`는 2 AZ 액티브-액티브. `worker`는 한 태스크가 죽으면 ECS가 다른 AZ에서 재기동한다. 조정 루프는 몇 분 멈춰도 카탈로그 조회에 영향이 없다(`06` §5)
- **클러스터 분리**: auth-proxy는 **전사 로그인 경로**다. 앱마켓 배포·장애와 섞으면 안 된다. ECS 클러스터는 무료이므로 분리 비용이 없다. 태스크 역할·배포 파이프라인도 분리한다
- **web/worker를 처음부터 분리**: `06` §5-1은 "지금은 한 서비스"로 두었으나, `web`을 2개 띄우면 조정 루프도 2개가 된다. Fargate에서 서비스 하나를 더 두는 비용은 태스크 1개뿐이다
- **advisory lock**: desiredCount 1만으로는 롤링 배포 중 두 태스크가 겹칠 수 있다. 리더 보장은 인프라 설정이 아니라 DB 락으로 한다
- **NAT를 auth-proxy에만**: market이 인터넷에 나갈 이유는 Cognito뿐이고, 그것도 프록시를 거친다(`AXM-0015`). 보안성(①)

## 결과

**얻는 것**
- 배포 단위: 이미지 2개(앱마켓, 프록시), 서비스 3개
- 전사 로그인 경로와 앱마켓의 장애 범위가 분리된다

**감수하는 것**
- Fargate는 태스크 기동이 EC2보다 느리다. 저트래픽이라 오토스케일링 반응 속도는 문제되지 않는다
- 프라이빗 서브넷에서 이미지를 받으려면 VPC 엔드포인트 여러 개가 필요하다(엔드포인트 시간당 과금)

## 검토한 대안

| 대안 | 평가 | 기각 사유 |
|---|---|---|
| EKS | 온프렘 VKS와 운영 방식 통일 | 서비스 3개를 위해 클러스터 운영. 운영 용이성(⑤)에 역행 |
| EC2 | PoC 연장선 | 노드 패치·AMI 관리. 운영 비권장 (`05` §5-2) |
| 단일 클러스터 | 관리 대상 감소 | 앱마켓과 전사 로그인 경로의 경계가 흐려진다. 분리 비용 0 |
| web · worker 단일 서비스 | `06` §5-1 초안 | web 2개 = 조정 루프 2개. 분리 비용이 태스크 1개 |
| Lambda (worker) | 서버리스 | 15분 한도, 조정 루프 순회 시간이 늘면 걸린다. 같은 이미지·코드베이스 원칙과 어긋남 |

## 미결 / 후속

- 목표 수량(앱 수 · 동시 사용자 · SLA) 확정 후 사양·오토스케일링 기준 재산정 (`03` §8 #12)
- Aurora vs RDS PostgreSQL 인스턴스 선택
- 공유 네트워크 계정이 생기면 auth-proxy 클러스터·NAT 이전 검토 (`AXM-0015`)
