# AXM-0005: Databricks Apps 비용 통제 — 유휴 정지 의무와 공용 웨어하우스 강제

- **상태**: Accepted
- **일자**: 2026-09-12
- **결정자**: 플랫폼 / 재무 협의 필요
- **관련 문서**: `04-cost-model.md`, `02` §6-1, `03` §3 3층

## 맥락

선행 문서들은 "Medium 0.5 DBU/h, 실행 중 상시 과금"을 사실로만 기록하고 **총량을 계산하지 않았으며, 앱 컨테이너 단가만 보고 있었다.** 실제 비용 구조를 계산한 결과 두 가지가 드러났다.

1. **Databricks Apps에는 auto-stop이 없다.** SQL Warehouse와 달리 유휴 자동 정지 설정이 존재하지 않는다. 방치하면 실질적으로 24/7 과금이며, 사내 업무앱의 실사용률을 감안하면 **구조적으로 70~85%가 낭비**된다
2. **비용의 지배 항목은 앱 컨테이너가 아니라 뒤에 붙는 SQL Warehouse다.** 서버리스 Small = 12 DBU/h로 앱 Medium의 **24배**다

규모로 보면 상시 구동 앱 100개는 앱 컨테이너만으로 **연 3~6억원** 수준이고, 앱마다 전용 웨어하우스를 붙이면 **연 30억원대**가 된다.

## 결정

> **(1) 유휴 정지를 플랫폼 의무로 구현한다. (2) 공용 SQL Warehouse를 강제하고 앱 전용 웨어하우스 생성을 금지한다.**

- 유휴 정지: Apps REST API를 호출하는 스케줄 잡 또는 유휴 감지 정지를 **스캐폴드와 플랫폼 운영에 기본 탑재**한다. 기준은 평일 09–18시 구동
- 공용 웨어하우스: `02` §6-1의 `validate` 스테이지에서 앱 설정이 승인되지 않은 전용 웨어하우스를 참조하면 **파이프라인을 실패**시킨다
- 3층 기본값(`03` §3)은 **이 두 통제가 구현되어 있는 동안에만** 유효한 조건부 기본값으로 한다

## 근거

- 평일 업무시간 제한 시 **약 70% 절감**(110/365 DBU). 실측 사례에서는 76%(주 50시간 vs 168시간)
- 방치의 실제 비용: 테스트 앱 하나가 69일간 유휴 상태로 약 $800 소진
- **앱마켓은 정의상 롱테일 앱이 많은 카탈로그**이므로 이 실패 모드가 예외가 아니라 기본값이 된다
- OBO가 사용자 신원을 그대로 전달하므로 **웨어하우스를 공유해도 권한 분리는 유지**된다. 전용 웨어하우스를 둘 보안상 이유가 없다
- 3층 기본값의 실제 비교 대상은 "DBU 단가 vs 클라우드 VM 단가"가 아니라 **연 수억원 vs 거의 0**이다. VKS는 기구축 온프렘 하드웨어라 파드 하나의 한계비용이 0에 가깝다

## 결과

**얻는 것**
- 앱 수가 늘어도 비용이 선형으로 따라 오르지 않는다
- 100개 한도가 **예산 가드레일**로 기능한다. 워크스페이스 증설은 용량 판단이 아니라 예산 승인 항목이 된다

**감수하는 것**
- **콜드 스타트가 사용자 경험의 일부가 된다.** 마켓 UI에 "정지됨 → 시작" 상태와 대기 경험을 설계해야 한다
- 정지 정책의 SLA 예외(24×7 요구 앱)를 별도로 관리해야 한다
- 공용 웨어하우스는 단일 실패 지점이 되고, 사이징·동시성 관리가 플랫폼 책임이 된다

## 검토한 대안

| 대안 | 평가 | 기각 사유 |
|---|---|---|
| 각 팀에 비용 책임만 지우고 통제는 하지 않음 | 자율성 | showback만으로는 늦다. 방치된 앱은 소유자가 관심을 잃은 앱이므로 청구서를 봐도 반응하지 않는다 |
| Large 대신 Medium 강제 | 절감폭 작음 | 이미 Medium이 기본값. 구동 시간이 문제이지 인스턴스 크기가 문제가 아니다 |
| 앱 전용 웨어하우스 허용 + 짧은 auto-stop | 팀 자율 | 앱 수십 개가 산발적으로 질의하면 유휴 5분이 채워지지 않는다. 100개 기준 연 30억원대 |

## 미결 / 후속

- **Apps SKU의 실효 단가** — `system.billing.list_prices` 쿼리로 확정 (`04` §1-2). 이 값 하나가 모든 금액 밴드를 단일값으로 만든다
- **콜드 스타트 시간 측정** — 30초면 온디맨드 시작 모델이 성립하고, 3분이면 마켓 UX를 다시 설계해야 한다
- 과금 최소 단위 확인
- 앱별 비용 귀속(showback) 구현 — `system.billing.usage` + `created_by`
- 비용 부담 주체 결정 (앱 소유 조직 / 플랫폼 예산)
